# Device capture: QR/camera + GPS

The framework ships two reusable capture primitives, both platform-agnostic and
ported from `weha-ai-hrd-mobile`:

- **QR / barcode scanning** — `src/lib/scan/qr-session.ts` + the reusable
  `<QrScanner>` component (`src/components/scan/qr-scanner.tsx`).
- **GPS fixes** — the `bridge.location` capability
  (`src/platform/renderer-location.ts`, mirrored in `electron/preload.ts`).

A working reference is the sample page **`/scan-locate`**
(`src/app/scan-locate/page.tsx`), reachable from the sidebar under **Scan**
(permission `transactions.use`). Copy it as the starting point for a real
feature (asset check-in, delivery proof, job lookup, …).

## Using the QR scanner

```tsx
import QrScanner from '@/components/scan/qr-scanner';

<QrScanner
  onScan={(text) => console.log('decoded', text)}
  onCancel={() => setScanning(false)}
  title="Scan asset tag"
  error={scanError}            // optional { code, message } to display
/>
```

The component owns the `<video>` element and **always releases the camera on
unmount**. Decoding uses the native `BarcodeDetector` where available
(Chrome/Android) with a `jsQR` fallback (Safari/iOS). `onScan` fires once with
the first decoded string, then the session stops itself.

For lower-level control (no UI), use `createQrSession(video, { onText })` from
`src/lib/scan/qr-session.ts`.

## Using GPS

```ts
const supported = (await bridge.location.permission()) !== 'unsupported';
const fix = await bridge.location.getCurrent();  // { latitude, longitude, accuracyMeters, capturedAt }
```

- `getCurrent()` throws `Error('permission_denied' | 'timeout' | 'unavailable' | 'unsupported')`.
- `requestPermission()` resolves `'granted' | 'denied'` (a fix request is what triggers the OS prompt).
- `accuracyMeters` is the device-reported radius — treat it as evidence, not a guarantee.

## Platform notes

| Target | QR/camera | GPS |
|---|---|---|
| web / PWA | `getUserMedia` (HTTPS or localhost required) | `navigator.geolocation` |
| Capacitor | same web APIs in the WebView | same |
| Electron | renderer `getUserMedia` | preload `navigator.geolocation` (no IPC) |

### Android

`android/app/src/main/AndroidManifest.xml` declares `CAMERA`,
`ACCESS_FINE_LOCATION` and `ACCESS_COARSE_LOCATION` (plus `POST_NOTIFICATIONS`
for push). Runtime prompts are triggered by the first `getUserMedia` /
`getCurrentPosition` call.

### iOS

iOS permission strings must be present in `Info.plist` **before** the first
capture, or the OS denies silently. The native `ios/` project is generated by
`npx cap add ios` (not committed here). After generating it, add:

```xml
<key>NSCameraUsageDescription</key>
<string>Scan QR codes to look up or check in items.</string>
<key>NSLocationWhenInUseUsageDescription</key>
<string>Capture your location for attendance or delivery proof.</string>
```

(For background location — not used here — you'd also need
`NSLocationAlwaysAndWhenInUseUsageDescription`.)

## Not included

**RFID/NFC** is not implemented. If a device app needs it, the natural seam is
the existing `hardware.serial` / `hardware.exchange` bridge (Electron, serial/USB
readers) or WebHID/WebUSB on web — a separate integration, not part of this
capture module.
